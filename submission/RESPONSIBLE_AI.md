# AI usage and responsible-AI notes

## Where AI is used
1. **Inside the product:** NVIDIA Nemotron models through Meterless Nightshift act as the Planner, Finder, Skeptic and Reporter. They plan retrieval, propose and attack candidate links between incidents, and write the report. They do not access the database, and nothing they say is trusted without a code check.
2. **To build it:** the code was written with help from **Claude Code (Anthropic)**. The team directed the work and reviewed and ran the results; the test suite and the offline Docker flow are run in CI; the team reports it also ran the live Zetaris/Nightshift flow by hand (no live trace is committed).

## What the system is for, and what it is not
It helps an analyst *find leads*: records at different stations that may belong to one series. It does **not** identify people, predict crime, score individuals, or make any determination of guilt. Output is labelled "lead / candidate link"; the report says so, and a human decides what to do.

## Design choices that limit harm
- **Models cannot invent evidence.** Every incident id, evidence id, quotation and attribute a model cites is re-checked in code against the retrieved records. Ungrounded citations are dropped or flagged, and the response says so.
- **A second model attacks the first.** The Skeptic runs on a different, larger model, is not shown the Finder's confidence, and may demand more retrieval. Open objections cannot be removed from the report.
- **"No" is allowed.** Without independent corroboration the answer is "no supportable link", with the reason. Duplicate or derivative reports are never counted as corroboration, and contradictions (a forensic exclusion, a witness/CCTV colour conflict) are surfaced, not merged away.
- **Honest numbers.** Scores are labelled "uncalibrated heuristic, not a probability". Nothing is presented as accuracy it has not earned. The UI no longer carries hard-coded certainty (the earlier "Certified Admissible", "100% Citation Grounding" and "ALL SENTINELS GREEN" strings, invented fallback evidence cards and a hard-coded model list were removed).
- **Transparent degradation.** If a model or service is unavailable the run says which part fell back, in the trace (`fallback_reason`, `source: replayed | code_fallback | local_sample`) and the response. A replayed or code-generated step is never presented as a live model call. The UI derives grounding, verifier and Skeptic status from the API response and shows "not available" (Skeptic: not run) when a field is absent. The frontend type-check and build pass; the UI was not visually checked in a browser or tested against a real API response.
- **Bounded and auditable.** Hard caps on iterations, model calls and time; read-only SQL; one JSONL trace per run (agents, handoffs, query ids, engine events, requested and answering model).
- **Memory is gated.** H-MEM stores only leads that passed the verifier and the Skeptic, behind a secret gate and a confidence floor; prior memory is context, never evidence. Decision memory (`backend/app/services/decision_memory.py`) lets a prior verified lead that overlaps a new question's incident ids or attribute tokens change that run's retrieval order: its incident ids are fetched first as a starting hypothesis. The write gate is unchanged (verifier SUPPORTED, Skeptic review done, no open high-severity objection). Links the verifier rejected or the Finder withdrew are suppressed and flagged, never promoted. The effect is returned as `memory_influence` and logged as a trace event, so it can be audited. Memory ids (`DMEM-`) are not valid evidence ids (the verifier ignores them, covered by tests), so memory cannot raise a link to SUPPORTED or count as an independent source. Matching is lexical, not semantic, and no real-model run has shown memory changing a live outcome (the tests use scripted, labelled models).
- **Privacy and secrets.** All data is synthetic. No tokens reach the frontend or logs; a secret scan covers the repo and the Docker image; `.env` is never in the image.

## Known limitations and risks
- **Bias.** Linking depends on what was recorded and how. A real deployment would inherit recording and reporting biases (e.g. which areas are patrolled, how officers describe methods). We have not measured fairness because the data is synthetic.
- **Conservative results.** The recorded judge examples (`output_examples/`, three WEAK links for the catalytic-converter question and "no supportable link" for the other two) predate the retrieval change, which altered the candidate sets and therefore the prompt hashes. Recorded model responses are keyed by prompt hash, so they no longer match every prompt; offline runs fall back to the labelled code-only path for those. The recordings and `output_examples/` were not re-recorded (that needs live Nightshift credentials), and `scripts/judge_compare.py` is expected to fail against the committed examples until they are; this has not been confirmed against a running server. Those earlier results were the verifier working as designed (the evidence did not independently corroborate the series), and they never demonstrated recall on the planted series. The retrieval fix now surfaces 7 of the 8 planted incidents in series 001-003 (the oldest of each series included) in the local-sample mirror; INC-NORTH-0294 is still missed. The new SQL ranking was not run against live Zetaris.
- **Benchmark caveat.** No real-model evaluation result exists. `evaluation/results.json` is produced by a scripted offline stand-in (hand-written planner/finder logic, no model called), is stamped "NOT A MODEL BENCHMARK" and no longer emits fake model receipts; it tests the pipeline, verifier and scoring mechanics only. A pre-registered protocol (`evaluation/PREREGISTRATION.md`, status "not yet run") and a `--live` harness mode (real Nemotron via Nightshift against a Lightning-only baseline) now exist, but the live mode has never been run. The original seven cases are a development set. A frozen 12-case held-out set exists, but it is held out only of tuning, fixed by hash, and reuses the same synthetic generator and planted series, so it does not test generalisation to real data.
- **Model behaviour varies.** Model outputs are non-deterministic; offline sample mode replays recorded responses for reproducibility, and prompts without a recording use a weaker, labelled code-only fallback. After the retrieval change more prompts lack a recording, so more offline steps take that fallback path.
- **Heuristic verifier.** Its contradiction and duplicate checks cover the patterns in our data, not all real-world patterns.
- **Scope.** Synthetic data, three stations, five sources. Moving to real data would need legal basis, consent and oversight, a privacy and bias review, calibrated confidence, and a human-in-the-loop policy.
